# Agent、middleware 与 checkpointer

`createAgent` 是 LangChain v1 里搭建 Agent 的主要入口。传入模型、工具列表和系统提示词，它就会生成一个可以反复"思考—调用工具—观察结果"的运行时。相比旧版 AgentExecutor，它的配置更直观，并且可以直接接入 LangGraph 的能力，比如持久化状态和中间件。

Agent 的核心是一个循环：模型先判断当前该不该调用工具，如果返回工具调用请求，运行时执行对应工具，把结果包装成工具消息追加到对话里，然后再次请求模型；直到模型给出最终回答为止。因此设计 Agent 时要关注三件事：提示词是否清楚说明职责边界，工具描述是否准确，工具失败时是否有可读的错误信息。工具描述写得好，模型选错工具的概率会明显下降。

Middleware 是 v1 引入的扩展点，用来在 Agent 执行流程中插入通用逻辑，而不必修改业务代码。常见的内置中间件包括：上下文过长时自动摘要历史消息、对失败的工具调用重试、在敏感操作前暂停等待人工确认。自己写中间件时最常用的是包装工具调用的钩子，可以在调用前校验参数、调用后统一记录日志，或者在异常时返回一条友好的提示，让 Agent 有机会自行纠正而不是直接崩溃。

Checkpointer 解决的是记忆问题。模型本身无状态，多轮对话靠把历史消息一起发送来实现。如果每次都手动维护消息数组，会话一多就容易混乱。checkpointer 的做法是：Agent 每执行一步就把完整状态写入存储，调用时传入一个 `thread_id` 作为主键，下一轮用同一个 `thread_id` 调用时会自动读回历史，再追加新消息。

`MemorySaver` 是最简单的 checkpointer，数据只存在当前进程的内存里，进程退出就丢失，适合本地学习和演示。生产环境应当换成基于 SQLite、Postgres 或 Redis 的持久化实现，并考虑线程隔离、状态清理和并发写入的问题。

把三者放在一起看：`createAgent` 提供骨架，middleware 负责横切关注点，checkpointer 负责会话状态。它们各自解决一类问题，组合起来才是一个可用的 Agent 服务。开发阶段建议先用内存 checkpointer 跑通流程，再用中间件补齐摘要、重试和人工确认，最后再替换为持久化存储。
