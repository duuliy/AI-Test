# LangChain 基础概念

LangChain 把与大模型交互的过程拆成可组合的模块：模型、消息、工具和 Agent。理解这四层，才能看懂后面的 RAG 与中间件。

## 模型

模型负责推理和生成。本项目通过 OpenAI 兼容协议访问模型，只改 `OPENAI_BASE_URL` 和 `OPENAI_MODEL` 就能切换供应商。模型本身是无状态的，它不会记住上一次对话，所谓“记忆”都是把历史消息重新发给它。

## 消息

消息是对话的基本单位。`HumanMessage` 表示用户输入，`AIMessage` 表示模型输出，`ToolMessage` 表示工具执行结果。模型决定调用工具时，会在 `AIMessage.tool_calls` 里给出工具名、参数和调用 id；本地执行完后，必须用相同 id 的 `ToolMessage` 回填，模型才知道这次调用的结果。

消息的 `content` 有两种形态：字符串，或内容块数组。内容块可能是文本、图片、推理过程等，展示时只应拼接 `type` 为 `text` 的块，否则容易把对象直接转成无意义字符串。

## 工具

工具不是模型自带的能力，而是本地进程里的普通函数。我们用 `tool()` 把函数、名称、描述和 Zod schema 注册成工具。描述决定模型何时调用，schema 决定参数如何填写，真正执行永远发生在本机。工具应返回字符串，并对可预期的业务错误返回错误文案，而不是抛出异常打断整个循环。

## Agent

Agent 把“调用模型、执行工具、回填结果、再次调用模型”的循环封装起来。`createAgent` 接收模型、工具、系统提示词和可选的 checkpointer。模型只负责决策，执行和状态管理都在框架与本地代码中完成。

## 流式输出

模型生成一段长文本可能需要几秒到几十秒。一次性等待会让页面长时间空白；改用流式接口后，模型每产出一小段，前端就能追加显示。流式改变的只是交付方式，模型仍然是逐步生成，最终内容不会因此变短或变长。使用 `streamMode: "messages"` 时，可以逐片拿到文本，实现打字机效果。
