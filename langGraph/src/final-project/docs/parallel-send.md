# Send 并行分发与 reducer 汇总

## Send 的作用

Send 不是普通的边，它把一份独立输入投递给指定节点，一次可以投递多份。条件边返回 Send 数组时，LangGraph 会把这些分支并行调度。

每个 Send 分支只能看到自己收到的参数，看不到父图的完整状态，所以并行节点要设计成只依赖输入、可重复执行。

## 并行分支的汇总

并行分支结束后，LangGraph 等待全部分支完成再进入下游节点，这个动作叫 fan-in。分支返回的字段会按照状态通道的 reducer 合并。

如果字段是普通字段，后写入的分支会覆盖先写入的结果；要保留所有分支的产出，必须给字段配置 reducer，例如数组拼接或 Set 去重。

## 去重与来源

并行检索常见的重复来自不同子问题命中同一段文档。比较稳妥的做法是给每条结果保留 source 和 chunkIndex，用这两个字段组成去重键。

这样即使多个分支返回同一片段，最终 findings 里也只出现一次，并且每条结论都能追溯到具体文档和段落。

## recursionLimit

图在循环和并行扩展时会增加执行步数。recursionLimit 是运行时兜底，超过限制会抛出错误而不是无限执行；审批回流和自检循环都应该设置合理的上限。
